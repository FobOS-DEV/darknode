ТЗ: Telegram-бот для выдачи VPN-конфигов и управления клиентами

1. Цель проекта

Нужно разработать Telegram-бота для клиентов VPN, который:
- выдаёт пользователю его персональный VPN-конфиг
- показывает краткую инструкцию по подключению
- показывает статус доступа
- показывает срок действия
- даёт кнопку для связи с администратором в личных сообщениях Telegram для продления доступа
- поддерживает простую админскую панель/команды для управления пользователями
- хранит данные в базе
- работает как MVP без встроенной оплаты

Проект ориентирован на небольшой приватный VPN-сервис для знакомых/клиентов.

2. Основной сценарий использования

Пользовательский сценарий:
1. Пользователь открывает Telegram-бота
2. Нажимает /start
3. Бот определяет, есть ли пользователь в базе
4. Если пользователь найден и активен:
   - показывает кнопки:
     - Мой конфиг
     - Инструкция
     - Статус
     - Продлить доступ
5. По кнопке «Мой конфиг» бот выдаёт:
   - VLESS-ссылку
   - краткое пояснение
6. По кнопке «Инструкция» бот выдаёт:
   - какой клиент установить
   - как импортировать конфиг
7. По кнопке «Статус» бот показывает:
   - активен ли доступ
   - дату окончания
8. По кнопке «Продлить доступ»:
   - бот даёт кнопку/ссылку для перехода в личные сообщения к администратору

Если пользователь не найден:
- бот пишет, что доступ ещё не выдан
- и показывает кнопку «Написать администратору»

3. Требования к функционалу

3.1 Пользовательская часть

Команды:
- /start — стартовый экран и главное меню
- /config — выдать конфиг
- /status — показать статус доступа
- /help — выдать инструкцию
- /contact — дать ссылку на администратора

Кнопки главного меню:
- Мой конфиг
- Инструкция
- Статус
- Продлить доступ

Функция «Мой конфиг»:
Если пользователь активен:
- выдать:
  - имя клиента
  - VLESS-конфиг
  - краткую инструкцию
- желательно дать:
  - конфиг в виде текста
  - кнопку импорта через обычную ссылку

Если пользователь не активен:
- написать, что доступ не активен или истёк
- предложить связаться с администратором

Функция «Статус»:
Показывать:
- имя клиента
- статус: active / expired / disabled
- дата выдачи
- дата окончания
- желательно: сколько дней осталось

Функция «Инструкция»:
Выдавать понятный короткий текст:
- Android: v2rayNG / NekoBox
- Windows: v2rayN / Nekoray
- iPhone: любой совместимый Reality/VLESS клиент
- как импортировать конфиг по ссылке

Функция «Продлить доступ»:
Бот не продлевает сам, а:
- показывает текст «Для продления напишите администратору»
- даёт inline-кнопку «Написать Роме»
- кнопка должна вести в личные сообщения Telegram администратора

3.2 Админская часть

Нужно реализовать минимальный набор админ-команд.

Админ может:
- создать пользователя
- привязать Telegram user к VPN-клиенту
- изменить срок действия
- отключить пользователя
- включить пользователя
- посмотреть список пользователей
- посмотреть одного пользователя
- при необходимости обновить конфиг

Предлагаемые админ-команды:
- /admin — показать админ-меню
- /adduser — создать пользователя
- /setexpiry — выставить дату окончания
- /disable — отключить пользователя
- /enable — включить пользователя
- /listusers — список всех пользователей
- /userinfo — подробности по одному пользователю

Важно:
- админ-доступ должен быть ограничен по Telegram user id
- только администратор может использовать эти команды

4. Модель данных

Для MVP достаточно SQLite.

4.1 Таблица users
- id — integer primary key
- telegram_id — text/integer unique
- username — text nullable
- first_name — text nullable
- last_name — text nullable
- full_name — text
- is_admin — boolean default false
- created_at — datetime
- updated_at — datetime

4.2 Таблица vpn_clients
- id — integer primary key
- user_id — foreign key -> users.id
- display_name — text
- email_label — text
- uuid — text unique
- vless_url — text
- server — text
- port — integer
- public_key — text
- short_id — text
- sni — text
- flow — text
- status — text (active, expired, disabled)
- created_at — datetime
- expires_at — datetime nullable
- updated_at — datetime

4.3 Таблица audit_logs
- id
- action
- actor_user_id
- target_user_id
- payload_json
- created_at

5. Бизнес-логика

5.1 Активный пользователь
Пользователь считается активным, если:
- есть запись vpn_client
- status = active
- expires_at пустой или больше текущего времени

5.2 Истечение срока
Если текущая дата > expires_at, бот должен:
- считать пользователя expired
- не выдавать активный доступ как рабочий
- предлагать написать администратору

5.3 Выдача конфига
Бот выдаёт только конфиг, привязанный к конкретному Telegram user.
Пользователь не должен видеть чужие конфиги.

5.4 Продление
На этапе MVP:
- бот не продлевает автоматически
- админ вручную меняет expires_at
- после этого пользователь снова видит активный статус

8. UX-требования

Тон сообщений:
- коротко
- понятно
- без лишней воды
- дружелюбно, но не маркетингово

Пример /start:
Привет. Здесь ты можешь получить свой VPN-конфиг, посмотреть статус доступа и инструкцию по подключению.

Пример «Статус»:

Имя: Анна Шкинева

Пример «Продлить доступ»:
Чтобы продлить доступ, напиши администратору в личные сообщения.

9. Безопасность

Обязательно:
- не отдавать конфиги неавторизованным пользователям
- все админ-команды ограничить по ADMIN_TELEGRAM_ID
- логировать админские действия
- не хардкодить токен бота
- не светить внутренние служебные ошибки пользователю

10. MVP scope

Входит в MVP:
- бот
- SQLite
- /start
- выдача конфига
- инструкция
- статус
- кнопка связи с админом
- базовые админ-команды
- поддержка срока действия

Не входит в MVP:
- встроенная оплата
- автосоздание VPN-клиента на сервере
- веб-админка
- аналитика трафика в боте
- личный кабинет через сайт
- реферальная система
